<objective>
Add a `'use server'` file-level directive to `web/src/lib/dashboard/actions.ts` and layer 5 mutation methods on top of the existing sanitization helpers. Each mutation: (1) writes to Postgres via Phase 2 Drizzle queries, (2) calls `revalidateTag('dashboard-payload', 'max')` AFTER the write commits, (3) bubbles errors to the route handler (Plan 03-05) which logs via `log()` (SVC-03).

Purpose: Centralize cache-tag invalidation in ONE file so every mutation path goes through the same chokepoint (Pattern Map cross-file rule #6). This is the consequence of Research Critical Finding #1 — `updateTag` is Server-Actions-only, route handlers cannot call it directly. The `'use server'` facade is the canonical path.
Output: Single file `web/src/lib/dashboard/actions.ts` with the file-level `"use server"` directive, 5 new exported async mutation functions, and unchanged existing sanitization exports. The legacy `actions.ts` reconciliation is path (b) per CONTEXT D-37 / Claude's Discretion (line 235): keep actions.ts as a thin facade over `lib/db/queries`. Path (a) is rejected because route handlers calling Drizzle + revalidateTag inline duplicates invalidation logic across 6 routes.

Reconciliation note vs. ROADMAP SVC-05: ROADMAP literally says "delete `lib/dashboard/actions.ts`". CONTEXT D-37 + Claude's Discretion line 236 explicitly resolve the contradiction: SVC-05 in Plan 03-08 deletes the **legacy non-`use server` parts** (anything Sheets-era), and Plan 03-04 adds the new `'use server'` mutation facade in the SAME file. Result: `actions.ts` exists post-cutover but its body is fully rewritten; SVC-05's "delete" semantic is realized by the absence of any pre-cutover Sheets-era code (e.g. `setStudentActionInSheets`-style functions that never lived here anyway — those lived in `lib/sheets/actions.ts` per Pattern Map line 16).

Decision (Claude's Discretion CONTEXT line 236): chosen path (b) — single-file facade. Rationale: 5 mutations × 6 routes = 30 potential invalidation sites if path (a) chosen; one file with one `revalidateTag` call per mutation is auditable in a single PR diff.

    ```ts
    /** SVC-03 / D-28 — single-student action set. */
    export async function setStudentAction(input: {
      studentKey: string;
      studentName: string;
      parentName: string;
      status: StudentActionStatus;
      updatedByEmail: string;
      updatedByName: string;
    }): Promise<void> {
      // 1. Postgres write FIRST (atomic upsert + log append)
      await upsertFollowUpState({
        studentKey: input.studentKey,
        studentName: input.studentName,
        parentName: input.parentName,
        status: input.status,
        updatedByEmail: input.updatedByEmail,
        updatedByName: input.updatedByName,
      });
      await appendFollowUpLog({
        studentKey: input.studentKey,
        studentName: input.studentName,
        parentName: input.parentName,
        status: input.status,
        actorEmail: input.updatedByEmail,
        actorName: input.updatedByName,
        actionType: "set",
      });
      // 2. Tag flush SECOND — only fires if both writes succeeded.
      revalidateTag(DASHBOARD_CACHE_TAG, "max"); // Critical Finding #1: NOT updateTag
      recordCacheInvalidation(new Date().toISOString());
    }

    /** SVC-03 / D-28 — single-student clear. */
    export async function clearStudentAction(input: {
      studentKey: string;
      studentName: string;
      parentName: string;
      actorEmail: string;
      actorName: string;
    }): Promise<void> {
      await appendFollowUpLog({
        studentKey: input.studentKey,
        studentName: input.studentName,
        parentName: input.parentName,
        status: null,
        actorEmail: input.actorEmail,
        actorName: input.actorName,
        actionType: "clear",
      });
      revalidateTag(DASHBOARD_CACHE_TAG, "max");
      recordCacheInvalidation(new Date().toISOString());
    }

    /** SVC-03 / D-25 / D-28 — bulk action via WebSocket Pool transaction. */
    export async function bulkSetAction(input: {
      updates: Array<{

        parentName: string;

      revalidateTag(DASHBOARD_CACHE_TAG, "max");
      recordCacheInvalidation(new Date().toISOString());

    /** SVC-03 / D-28 — mark student inactive. */
    export async function markInactiveStudent(input: {
    ```
