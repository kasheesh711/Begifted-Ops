<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → external Google Sheets | Operator clicks the link; new tab loads `docs.google.com`. The Sheets surface owns its own auth (Google Workspace SSO). |
| Source code → user-visible string | Hardcoded URL ships in the bundle; no secrets, but a malicious value would phish operators. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering (URL) | `ARCHIVE_ACTION_SHEET_URL` constant | mitigate | Operator-confirmed value via Task 1 checkpoint; PR review verifies the literal matches the Google Sheets URL the operator pasted. TODO marker forces explicit confirmation before merge. |
| T-03-05 | Information Disclosure (tabnapping) | external `<a target="_blank">` | mitigate | `rel="noopener noreferrer"` blocks `window.opener` access from the new tab and prevents Referer leakage of internal dashboard URL paths. |
| T-03-06 | Information Disclosure (URL leakage) | hardcoded sheet URL in client bundle | accept | URL points at Google Sheets which already enforces Workspace auth. Anyone outside the Workspace following the URL hits a Google sign-in / access-denied page. No PII or secrets in the URL itself. |
| T-03-07 | Repudiation (no link audit) | `<a>` click behavior | accept | The link is read-only; clicks don't mutate state. Phase 5 RETI-02 monitors Apps Script Moved-page hit logs for the 30-day tail — that's the audit channel. |
</threat_model>
